# 两周掌握计划

这个项目作为辅助后端项目，用两周形成可讲深度即可，把更多时间留给核心 Agent 项目。

| 天数 | 学习任务 | 当天产出 |
|---|---|---|
| 1 | 跑通登录、商铺、下单、查询结果 | 手画全链路图 |
| 2 | 精读 `seckill.lua` 与 claim/rollback 脚本 | 口述三个 Redis key 的含义 |
| 3 | 精读 RocketMQ 事务消息与回查 | 写出 COMMIT/ROLLBACK/UNKNOW 条件 |
| 4 | 精读消费者和 DB 事务边界 | 解释自调用事务失效 |
| 5 | 唯一索引、Redisson、消息重复 | 完成一人一单故障推演 |
| 6 | 本地可靠任务和延迟关单 | 画出宕机窗口与恢复路径 |
| 7 | 支付/关单状态机和对账 | 回答订单表为何是账本 |
| 8 | 多级缓存读链路 | 演示 L1/L2/DB 命中 |
| 9 | 缓存锁、逻辑/物理过期 | 解释旧锁误删场景 |
| 10 | 提交后驱逐与 Canal | 解释为什么 Canal 不是强一致 |
| 11 | 两层限流 | 推导令牌桶 refill 公式 |
| 12 | 安全修复与工程配置 | 演示越权被拒、路径穿越被拒 |
| 13 | 做一次小压测与数据核对 | 记录环境、吞吐、P95、成功订单数 |
| 14 | 模拟面试 | 90 秒介绍 + 10 个追问录音 |

每天控制在 2 到 3 小时。第 14 天后只做查漏补缺和一轮压测，把主要开发精力转回 Agent 项目。

## 掌握标准

满足以下条件就可以放简历：

- 不看文档能画 A 模式完整时序图。
- 能解释事务消息与本地任务分别解决哪个一致性窗口。
- 能从任意一个失败点说出是否重试、怎样幂等、最终由谁兜底。
- 能现场指出一处原实现问题并解释修复，而不是只介绍中间件。
- 有一份真实压测记录，即使结果不高也包含机器配置、参数和正确性校验。
