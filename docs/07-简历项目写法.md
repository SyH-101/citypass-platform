# 简历项目写法

## 推荐项目名

**CityPass｜城市活动预约与候补补位平台**

副标题可写：Java / Spring Boot / Redis / RocketMQ / MySQL / OpenResty。

## 核心简历描述（根据篇幅选 4—5 条）

- 将开源本地生活服务原型重构为城市活动发现与限量预约平台，统一 `Venue / ActivityPass / Reservation / Story / Subscription` 领域、REST API 与 MySQL 表结构，并提供 Docker Compose 一键环境。
- 设计预约请求事实表与 Transactional Outbox，在本地事务中持久化 `PROCESSING` 请求及 CREATE 投递意图；结合 Redis Lua 原子占位、MySQL 条件扣减和有效订单唯一索引防止超卖与重复下单。
- 实现 MySQL 严格 FIFO 候补与自动补位：以活动库存行串行化释放和入队，阻塞锁定真正队首；名额以递增 `resourceVersion` 交接，Lua 仅在旧/新归属版本匹配时执行转移。
- 将主动取消与超时关单拆分，以 `status=UNPAID AND offer_expire_time<=NOW()` 复合 CAS 处理支付/超时竞争；超时任务按实际资格截止时间执行，候补资格不超过活动结束时间。
- 构建支持多实例并发执行的可靠任务引擎，以任务级租约、执行版本和过期回收防止重复领取，并提供指数退避、DEAD 死信、Token 保护的重放接口与 Micrometer 积压/重试/补位延迟指标。
- 使用缓存版本水位与 Lua 条件写回阻止过期查询覆盖新数据，由与业务写同事务的失效 Outbox 触发 Redis Pub/Sub，广播驱逐所有 JVM Caffeine 与 OpenResty 缓存。

## 30 秒简历追问回答

> 我保留了开源原型的通用用户与内容能力，重构了 CityPass 领域和预约核心。HTTP 入口先用请求事实 + Outbox 可靠受理，取消或超时时以活动库存行串行化，严格锁定候补队首，再用带版本校验的 Lua 完成 Redis 名额交接。可靠任务支持多实例租约领取、死信和重放。我用真实 Docker 依赖验证了 100 用户竞争 10 个名额时恰好生成 10 笔有效订单，以及锁住队首、Broker 停机恢复和多 JVM 缓存失效。

## 可以写与不能写

| 可以写 | 原因 |
|---|---|
| Redis Lua 原子占位 | 代码和脚本已实现 |
| RocketMQ 削峰与重试 | Docker 环境已实际运行 |
| MySQL 严格 FIFO 候补与名额版本交接 | 有阻塞队首锁、状态机、事务和真实并发测试 |
| CREATE Transactional Outbox | 请求事实与投递意图同事务落库，已验证 Broker 停机恢复 |
| 任务级租约、死信与可观测性 | 有租约/版本、重试/DEAD/重放与 Micrometer 指标 |
| 版本化多级缓存 | 有条件写回与 Redis Pub/Sub 多 JVM 验证 |
| 基于开源项目二次开发 | 与事实一致 |

| 暂时不要写 | 原因 |
|---|---|
| 从零独立开发全部模块 | 通用能力来自开源基础 |
| 支撑十万 QPS | 未做规范压测 |
| 强一致分布式事务 | 设计目标是最终一致 |
| 完整支付系统 | 没有真实支付渠道 |
| 企业级权限 | 尚无 RBAC |

## 面试定位

这个项目适合作为第二项目，水平高于普通课程复刻，亮点集中在“候补补位 + 一致性”。它不需要抢 Agent 项目的篇幅。简历中给 4 条，面试时用一个名额从 DIRECT 用户转到 WAITLIST 用户的全过程证明深度。
