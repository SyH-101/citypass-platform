# 简历项目写法

## 推荐项目名

**CityPass｜城市活动预约与候补补位平台**

副标题可写：Java / Spring Boot / Redis / RocketMQ / MySQL / OpenResty。

## 四条简历描述

- 将开源本地生活服务原型重构为城市活动发现与限量预约平台，统一 `Venue / ActivityPass / Reservation / Story / Subscription` 领域、REST API 与 MySQL 表结构，并提供 Docker Compose 一键环境。
- 设计 RocketMQ 异步预约链路，使用 Redis Lua 原子维护库存、持有人与 claim，数据库以时间窗条件扣减和有效订单生成列唯一索引兜底，处理重复消息、超卖和取消后重新预约。
- 实现 MySQL 持久化 FIFO 候补与自动补位：按单调请求号排队，使用 `FOR UPDATE SKIP LOCKED` 选择队首，取消/超时后在事务中转移名额；通过本地可靠任务和幂等 Lua 同步 Redis 归属。
- 构建 OpenResty、Caffeine、Redis、MySQL 多级场馆缓存，在事务提交后主动驱逐，并提供可选 Canal binlog 失效链路；编写单元测试和端到端脚本验证支付 CAS、越权、补位、库存回补及活动时间窗。

## 30 秒简历追问回答

> 我不是简单改名。我保留了开源原型中的通用用户和内容能力，自己重构了 CityPass 领域，并重点实现预约候补。最难的是取消时不能简单加库存：有候补时名额要在同一个数据库事务中直接转移，Redis claim 再通过可靠任务幂等切换；只有队列为空才真正回补库存。项目用自动脚本验证了两级候补、支付竞争和取消后重新预约。

## 可以写与不能写

| 可以写 | 原因 |
|---|---|
| Redis Lua 原子占位 | 代码和脚本已实现 |
| RocketMQ 削峰与重试 | Docker 环境已实际运行 |
| MySQL FIFO 候补与自动补位 | 有状态机、事务和 E2E |
| 最终一致与可靠任务 | 有任务表、重试、幂等脚本 |
| 多级缓存 | 有 OpenResty/Caffeine/Redis/MySQL |
| 基于开源项目二次开发 | 与事实一致 |

| 暂时不要写 | 原因 |
|---|---|
| 从零独立开发全部模块 | 通用能力来自开源基础 |
| 支撑十万 QPS | 未做规范压测 |
| 强一致分布式事务 | 设计目标是最终一致 |
| 完整支付系统 | 没有真实支付渠道 |
| 企业级权限 | 尚无 RBAC |

## 面试定位

这个项目适合作为第二项目，水平高于普通课程复刻，亮点集中在“候补补位 + 一致性”。它不需要抢 Agent 项目的篇幅。简历中给 4 条，面试时用一个名额从 DIRECT 用户转到 WAITLIST 用户的全过程证明深度。
