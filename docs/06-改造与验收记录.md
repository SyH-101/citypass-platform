## 自动检查

```powershell
mvn clean test
docker compose config --quiet
docker compose exec -T openresty openresty -t
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\smoke-test.ps1
```

最近一次 Docker 验收覆盖：

- 直接预约 `DIRECT:4`：原订单取消。
- 候补补位并支付 `WAITLIST:2`。
- 补位前后 DB/Redis 库存均为 0。
- 剩余候补排位前移并可主动退出。
- 空队列取消后库存回补，同一用户可再次预约。
- 越权状态查询被拒绝，重复支付被 CAS 拒绝。
- 未来活动被 `FAIL_NOT_STARTED` 拦截。
- Canal Profile 下直接更新 `tb_venue`，缓存自动失效并读到新值；恢复更新再次收敛。

## 当前非生产能力

这些不是“漏实现”，而是项目范围边界：

- 支付只推进订单状态，没有接第三方支付回调和支付流水。
- 短信验证码写日志，未接短信供应商。
- 管理写接口只有登录校验，尚无组织者 RBAC。
- 没有前端、内容审核、审计后台、告警平台和多机压测报告。
- Canal 是已验收的可选 Profile，基础运行不强制启动它。

面试时主动说明边界会比把项目包装成生产系统更可信。
