# 改造与验收记录

## 代码审计发现与处理

| 严重度 | 原问题 | 处理 |
|---|---|---|
| 高 | DB 扣库存与插订单无事务 | 独立事务服务统一提交 |
| 高 | 取消状态、Redis 回补、DB 回补可能只完成一部分 | 状态与 DB 库存同事务，Redis 使用可靠任务幂等补偿 |
| 高 | 支付和结果查询未校验订单所有者 | SQL/查询同时校验 currentUserId |
| 高 | Mode B 回滚可能撤销别的订单 claim | claim 保存 orderId，Lua 比较所有权 |
| 高 | 上传删除存在目录穿越且上传接口匿名 | 规范化路径、图片白名单、登录保护、DELETE 语义 |
| 中 | 事务标记 TTL 后回查误回滚 | txn marker + 无 TTL claim owner 双重回查 |
| 中 | 订单已落库但延迟消息发送失败 | 本地可靠任务重试 |
| 中 | 缓存锁获取失败仍在 finally 删除锁 | token + Lua 所有权释放 |
| 中 | 缓存递归重试可能堆栈增长 | 有界循环等待 |
| 中 | 逻辑过期数据被重新写入 Caffeine | 过期值只返回当前请求，重建线程写新 L1 |
| 中 | 店铺事务提交前删缓存 | afterCommit 驱逐 |
| 中 | OpenResty 只缓存第一个响应 chunk | 累积完整响应后写缓存 |
| 中 | 令牌桶错误推进 last 时间 | 按 `refill/rate` 推进 |
| 中 | 登录验证码可复用、登出未完成 | 登录后删除验证码，实现 token 删除 |

## Docker 端到端验证

以下组件已在同一 Compose 网络中实际启动：MySQL 8、Redis 7、RocketMQ NameServer/Broker、Spring Boot、OpenResty，以及 Canal profile。MySQL、Redis、Broker 健康检查通过，应用成功连接三项基础设施。

| 验收链路 | 结果 |
|---|---|
| A 模式事务消息 | 秒杀受理后由 `WAITING` 收敛为 `SUCCESS`，DB/Redis 各扣 1 份库存 |
| B 模式普通消息 | 消费端 claim 与实际 orderId 一致，订单落库并支付成功 |
| 一人一单 | 同一用户第二次请求被拒绝 |
| 水平越权 | 另一用户无法查询或支付订单 |
| 支付 CAS | 首次支付成功，第二次支付失败 |
| 关单补偿 | TIMEOUT 后订单变为状态 4，DB/Redis 库存恢复，取消后支付失败 |
| 本地可靠任务 | `INIT_SECKILL_STOCK`、`ORDER_TIMEOUT`、`RESTORE_REDIS_STOCK` 均进入 `DONE`，重试数为 0 |
| 主动缓存失效 | 经应用更新店铺后，OpenResty/Java/Redis 返回新值；恢复操作同样生效 |
| Canal 缓存失效 | 直接 SQL 更新 `tb_shop` 后捕获 ROW binlog，经 RocketMQ 驱逐三层缓存并读到新值；恢复 SQL 后再次收敛 |
| 认证与接口边界 | 验证码登录后不能复用；登出后 token 失效；匿名写券和匿名上传均被拦截 |
| 自动冒烟脚本 | `scripts/smoke-test.ps1` 实跑通过 |

运行时额外发现并修复了四个部署问题：宿主机 MySQL 端口冲突、RocketMQ 持久化卷权限、OpenResty 默认 Host 含下划线、Canal 表过滤正则被双重转义。

15 分钟延迟档位已经由 Broker 配置并成功投递：已支付订单收到延迟消息后仍保持状态 2。为了缩短验收时间，未支付关单用同 Topic 的即时 `TIMEOUT` 消息验证，业务处理与真实延迟投递使用同一个消费者入口。
